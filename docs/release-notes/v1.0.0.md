OxiTide 1.0 is the first stable release of this unofficial TIDAL desktop client. It runs on Windows 10/11, and on Linux as a work in progress.

> OxiTide is an unofficial, third-party project. It is not affiliated with, endorsed by, or connected to TIDAL. A paid TIDAL subscription is required. OxiTide plays only what your own account can already stream.

## What's in 1.0

- **Playback engine:** a Rust engine with gapless playback, a streaming cache that prefetches the next track, offline playback of cached tracks, and recovery from network drops in place.
- **Bit-perfect output:** WASAPI exclusive and ASIO on Windows, ALSA direct hardware on Linux. When something changes the signal, OxiTide tells you.
- **Output picker:** one row per device, with its own Shared/Exclusive mode, nickname, icon, pin and hide, and a line for each device's supported formats. Pinned devices also appear in the player bar's quality menu.
- **Sound tuning (off by default):** a 10-band EQ, ReplayGain, crossfade, and AutoMix (experimental) transitions in Classic, Quick, Blend and Auto styles.
- **Three looks:** Atmosphere, Studio and Hi-Fi Rack, each light and dark.
- **Phone remote:** an opt-in web page for playback, the queue, search and your library, paired with a single-use QR code.
- **Library:** an editable own profile, a My Collection sidebar you can reorder, Save for Later, playlist folders and collaborators, and Undo for removals.
- **Desktop:** listening history and stats (stored locally), a sleep timer, tray, global hotkeys, media keys (SMTC / MPRIS), Windows taskbar controls, Discord Rich Presence, and Last.fm / ListenBrainz scrobbling with an offline queue.
- **Updates:** Windows installs and the Linux AppImage find new releases in **Settings → System → Updates**. Each update is verified against the release signing key.

### New since 0.7.0

- **Exclusive output plays at a fixed 100%.** On a device that has its own volume control (and on ASIO), exclusive mode leaves the level to the DAC or the system volume. The in-app volume shows 100% and is locked. Your slider position comes back when you return to shared mode. OxiTide no longer writes the device's own volume, which used to leave later shared sessions quieter. Before switching to exclusive, OxiTide warns you that playback may get louder; you can turn the warning off with "Don't show again".
- A device without its own volume control follows **If exclusive fails**: it either uses the in-app volume (not bit-perfect below 100%) or refuses to open.

## Install

| Platform | File |
|---|---|
| Windows 10/11 (x64) | `OxiTide_1.0.0_x64-setup.exe` (per user, recommended) or the `.msi` (per machine) |
| Linux (x86_64) | `.AppImage` or `.deb`; `PKGBUILD` for Arch (AUR recipe) |

Check downloads against `SHA256SUMS.txt`. An installed 0.3 or later copy offers the update in **Settings → System → Updates**. deb and AUR installs update through the package manager.

## Known limits

- **Windows builds are not code-signed.** SmartScreen shows "Windows protected your PC": choose **More info → Run anyway** after you check the hash. Updates are still verified against the release signing key.
- **The phone remote uses plain HTTP on your local network.** Another device on the same network could capture a paired phone's session and use the remote's (allowlisted) controls: playback, queue, favourites and adding to playlists. The remote is off by default. Revoke paired devices in Settings.
- **Debug builds only:** with the remote on, a development build proxies the phone page to the Vite dev server, so a LAN peer could read project source files. Release builds serve embedded files only.
- **One transitive advisory is accepted:** `zip` 4.6.1 (RUSTSEC-2026-0367/0368/0369), pulled in by Tauri's updater, the latest release. Every update archive is signature-checked before it is opened, and on Windows the updater runs the installer directly.

## Linux: work in progress

Linux builds, installs and plays (tested on CachyOS with KDE Wayland and PipeWire; Ubuntu 22.04 is the oldest base). Known issues:

- The "ALSA default, may resample" (`sysdefault:` / dmix) output entries can click on skip and seek. Use "System default" or the "(direct hardware)" entry.
- After OxiTide has held a DAC directly, PipeWire can lose that DAC until you replug it or run `systemctl --user restart wireplumber`.
- Switching from "System default" to the same DAC's exclusive entry takes about 5 s while PipeWire releases the card.
- Skip and seek on ALSA lag by up to ~150 ms (the buffer plays out to a faded end).
- The tray icon has no tooltip (libappindicator has no API for one).

## Performance

The scripted performance corpus (start-up, time to first sound, gapless advance, scrolling and filtering 10k-row lists, cache, a 2-hour soak, idle and tray, Hi-Fi Rack) passes its budgets on the release build. Budgets that were changed rather than met as first set:

- Memory budgets are the worst release run plus 15%.
- The 10k filter/sort scenario's frame p99 budget is 72 ms.
- Hi-Fi Rack memory (865 MB) and IPC (760 KB/min) were re-measured for WebView2 157: the rise came from the WebView, not the app.
- Gapless advance has no debt: the largest gap is 43 ms against a 100 ms budget.
