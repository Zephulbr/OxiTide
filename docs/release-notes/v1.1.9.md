OxiTide 1.1.9 fixes the Profiles page staying on "Loading…", works on networks where security software inspects secure connections, and makes connection problems easier to diagnose. Everything else is the same as in 1.1.8.

> OxiTide is an unofficial, third-party project. It is not affiliated with, endorsed by, or connected to TIDAL. A paid TIDAL subscription is required. OxiTide plays only what your own account can already stream.

## Fixes

- **Profiles no longer gets stuck loading the artists you follow** ([#10](https://github.com/Zephulbr/OxiTide/issues/10)). When TIDAL reported far more items than a list really holds, OxiTide kept asking for empty pages up to that number. It now stops after a long run of empty pages, while still reading past the short gaps that unavailable tracks leave.
- **Your own profile shows right away.** It no longer waits behind the artists you follow: it appears first on the page while they load, and stays there if they fail to load.
- **Leaving and reopening a page starts a fresh load.** If a page's data was still loading after a minute, opening the page again used to wait on the same request. It now asks again.
- **Works with antivirus HTTPS scanning and company proxies.** Some antivirus programs and corporate networks inspect secure connections by re-signing them with their own certificate, which they add to Windows (or Linux). Browsers and TIDAL's own app trust it; OxiTide did not, so it could not reach TIDAL. OxiTide now trusts the certificates installed on your system as well as its built-in ones.
- **A clear message when a secure connection fails.** If something on your network still blocks or tampers with the connection to TIDAL, OxiTide now says so ("Couldn't connect securely to TIDAL — something on your network may be interfering…") right away, instead of retrying and then showing a technical error. The log names the likely causes too.
- **Better logs for long lists.** Each long list writes one line to the log with how many items TIDAL reported and how many came back, without account or playlist ids. If something still goes wrong, **Settings → Diagnostics → Open logs folder** has what we need.

## Install

| Platform | File |
|---|---|
| Windows 10/11 (x64) | `OxiTide_1.1.9_x64-setup.exe` (per user, recommended) or the `.msi` (per machine) |
| Linux (x86_64) | `.AppImage` or `.deb`; `PKGBUILD` for Arch (AUR recipe) |

Check downloads against `SHA256SUMS.txt`. An installed 0.3 or later copy offers the update in **Settings → System → Updates**. deb and AUR installs update through the package manager.

## Known limits and Linux

Unchanged from 1.1: Windows builds are not code-signed (SmartScreen: **More info → Run anyway** after checking the hash), the phone remote uses plain HTTP on your local network, and Linux is a work in progress with the known issues listed in the [1.0 release notes](https://github.com/Zephulbr/OxiTide/releases/tag/v1.0.0).
