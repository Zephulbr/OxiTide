## What ships

Changes since `v1.1.5`:

- `c78ad8d1` fix(remote): unavailable tracks no longer cut phone lists short (#4). The phone
  pager (`remote/paged.svelte.ts`) advanced by the rows received and ended at an empty page;
  TIDAL omits unavailable tracks from `items` but counts them in `total`. Plus, from a pass over
  the phone remote: lyrics and Now Playing links no longer refetch on every state event; a
  cleared search no longer brings back an in-flight reply; the error Retry is translated; Add all
  loads the whole list first; a playlist add is capped at 5,000; a malformed `%` in the address
  no longer throws at start-up.
- `7344367e` docs: `ui/design/DESIGN.md` paging/Add-all notes; smoke items.
- `4eddfb91` fix(remote): a tapped row plays the whole list, not the pages loaded; a start past
  the 5,000-track window plays the tapped track. (Done in a parallel session.) A **candidate**
  cause of #7 only: the report is about the desktop, and every desktop path (CollectionTracks
  `playFrom` / `playAll` / `shuffleAll` await `ensureAll`; `play_context_shuffled` and
  `shuffle_around_current` shuffle the whole list) loads and shuffles the full list. #7 stays
  open; the owner has asked the reporter where and how the shuffle was started. The release
  notes say "may be what #7 describes".
- `ef906b6f`, `7128b156` fix(paging): the desktop pager (`lib/pager.svelte.ts`), the phone pager
  and `TidalClient::get_all_pages` read every window up to the last known total, empty ones
  included, whatever total an empty window reports; `get_all_pages` no longer returns nothing
  when its first window is empty.
- No command, config, IPC or locale-catalog change. Rust change: `get_all_pages` only.
