## What ships

Changes since `v1.1.9`:

- `460575ff` fix(ui): favorite artists, albums and tracks keep the first row of each id and
  WARN when they drop any (`favorite <list>: dropped N repeated rows`); Profiles draws each
  artist once; `RoutedPage` wraps every page in a `svelte:boundary` (ErrorState + Retry in
  the page's place), and the new `log_page_error` command logs `page <route> failed to draw:
  …` at ERROR. The likely cause of the #10 reporter's stuck Profiles on 1.1.9 (a repeated id
  in the keyed grid throws `each_key_duplicate`), reproduced in a component test, not yet
  confirmed on their machine.
- `fbddbd9f` fix(ui): the failed-page line names the route only, never its ids.
- One new IPC command (`log_page_error`, async, `NOT_EXPOSED` to the remote). No config,
  persisted-state or locale change (the boundary's message goes through `error.detail`).
