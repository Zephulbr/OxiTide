**Goal:** Close Track 9's a11y acceptance criteria (T9-D7, spec §6.4) by fixing the audited widget list, adding minimal jsdom component tests for the keyboard/focus contract, and recording keyboard/NVDA/contrast smokes.

**Architecture:** Small, focused fixes per widget with pure logic extracted to `ui/src/lib/` where possible; component behavior pinned by per-file jsdom tests (`// @vitest-environment jsdom`) using `@testing-library/svelte`; no global vitest config change (spec §5.5). **Spec:** `docs/superpowers/specs/2026-10-05-track9-ui-completion-design.md` (§6.4 is the authoritative fix list; §5.5 the test-infra contract; T9-D7 the six ACs)

## Global Constraints

- Svelte 5 runes only (`$state`, `$props`, `$effect`); no Svelte 4 stores, no `export let`.
- Components consume **semantic tokens only** (`--surface-*`, `--text`, `--accent`, …); never base or `--dyn-*` values directly, and never branch on mode/theme.
- Zero `svelte-ignore` comments: a11y warnings are fixed, not suppressed (spec §4 baseline: zero today).
- Strings stay component-local and untangled (i18n is out of scope, spec §2).
- No new remote origins, commands, DTOs, or disk caches. This plan changes UI code and UI tests only.
- Test environments: pure-logic tests stay in the default `node` environment; component tests opt in per file with `// @vitest-environment jsdom` as the **first line**. Clean up with `afterEach(cleanup)` from `@testing-library/svelte` (no `globals` config).
- Every task keeps these green before its commit: `npm --prefix ui run check` and `npm --prefix ui test`. Run `cargo test --workspace` + `cargo clippy --workspace -- -D warnings` in the final verification task (no Rust changes expected).
- PM-D1: this milestone must not regress boot or scroll budgets; TrackTable/VirtualList changes re-run S5/S6/S7 in Task 14 under unchanged `scripts/perf/budgets.json`.

## Review Focus

These are the inputs/conditions the spec implies but per-widget tests cannot fully cover — each has a task that pins the nearest test, and the rest are human-smoke items (Task 14):

1. **Global shortcut double-fire** — arrow/Home/End/Page keys handled by SeekBar, tabs, SortSelect, and the track table also reaching `App.onKeydown` and seeking/volume-stepping a second time. Pinned by the `event.defaultPrevented` guard (Task 9) plus the App smoke rows.
2. **Focus restoration when the opener vanished** — menu → Modal chains close the menu before the Modal mounts; a navigated-away row restores nothing. Pinned by `isConnected` guards in Task 2/4 tests.
3. **Roving focus over virtualized/filtered lists** — a focused row index can go stale when the list shrinks or the filter drops rows. Pinned by the clamped `focusRow` in Task 7 and the QueueRail setsize assertions in Task 8.
4. **Portal + inert layering** — the portaled Dialog must stay above grain/queue but below the context menu and toasts, and `.app` must stay interactive again after close. Pinned by Task 3's registry/portal tests; layering is a human visual row in Task 14.
5. **`aria-modal` sheets without `inert`** — the Mini queue sheet promises modality through `aria-modal`/focus trap/backdrop only; a screen reader that ignores `aria-modal` can still read the Mini background. Pinned by the Task 14 NVDA row.

Create `ui/src/lib/focusTrap.ts`:

```ts
const FOCUSABLE =
  'a[href], button:not([disabled]), input:not([disabled]), select:not([disabled]), ' +
  'textarea:not([disabled]), [tabindex]:not([tabindex="-1"])';

export function focusables(root: HTMLElement): HTMLElement[] {
  return Array.from(root.querySelectorAll<HTMLElement>(FOCUSABLE));
}

/// Svelte action for dialog-like surfaces: focus the first control, keep
/// Tab/Shift+Tab cycling inside `node`, and restore the mount-time focus on
/// destroy (guarded so an unmounted opener is not resurrected).
export function focusTrap(node: HTMLElement, options: { restore?: boolean } = {}) {
  const previous = document.activeElement instanceof HTMLElement ? document.activeElement : null;
  (focusables(node)[0] ?? node).focus();

  function onKeydown(event: KeyboardEvent) {
    if (event.key !== "Tab") return;
    const list = focusables(node);
    if (list.length === 0) {
      event.preventDefault();
      node.focus();
      return;
    }
    const current = document.activeElement instanceof HTMLElement
      ? list.indexOf(document.activeElement)
      : -1;
    const next = event.shiftKey
      ? current <= 0
        ? list.length - 1
        : current - 1
      : current === -1 || current === list.length - 1
        ? 0
        : current + 1;
    event.preventDefault();
    list[next].focus();
  }

  node.addEventListener("keydown", onKeydown);
  return {
    destroy() {
      node.removeEventListener("keydown", onKeydown);
      if (options.restore !== false && previous?.isConnected) previous.focus();
    },
  };
}
```

Create `ui/src/lib/portal.ts`:

```ts
/// Svelte action: render the node at the document body so ancestors with
/// transforms/animations or `inert` cannot clip or disable it. The overlay is
/// `position: fixed`, so leaving its Svelte parent visually changes nothing.
/// Moving a subtree that holds focus disconnects the focused node (browsers
/// reset focus to body), so re-apply it after the move — the Modal's
/// focusTrap action runs before this one.
export function portal(node: HTMLElement) {
  const active = document.activeElement;
  document.body.appendChild(node);
  if (active instanceof HTMLElement && node.contains(active)) active.focus();
  return {
    destroy() {
      node.remove();
    },
  };
}
```

/// Shift+F10 / the ContextMenu key -> show at the node's box. The node is

export function menuFor(node: HTMLElement, items: () => MenuItem[]) {
  function onContextMenu(event: MouseEvent) {
    event.preventDefault();
    menu.show(event.clientX, event.clientY, items(), node);
  }
  function onKeydown(event: KeyboardEvent) {
    if (event.key !== "ContextMenu" && !(event.key === "F10" && event.shiftKey)) return;

/// Keyboard seek target: arrows ±5 s, Page keys ±10 % of the duration (or
/// ±10 s when the duration is unknown), Home/End to the bounds. Returns null
/// for keys the control ignores (End is null while the duration is unknown).
export function seekByKey(key: string, position: number, duration: number): number | null {
  const known = duration > 0;
  const clamp = (value: number) => Math.max(0, known ? Math.min(duration, value) : value);
  const page = known ? Math.round(duration / 10) : 10000;
  switch (key) {
    case "ArrowLeft":
      return clamp(position - 5000);
    case "ArrowRight":
      return clamp(position + 5000);
    case "PageUp":
      return clamp(position + page);
    case "PageDown":
      return clamp(position - page);
    case "Home":
      return 0;
    case "End":
      return known ? duration : null;
    default:
      return null;
  }
}
