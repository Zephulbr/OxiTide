## 1. Purpose

Every piece of interface text is English, written inline in ~300 UI files (a rough count on
2026-11-12: ~1,550 strings; Settings ~470, Hi-Fi Rack ~200, phone remote ~120, plus the
tray menu and taskbar buttons in Rust). Dates are English in places (`historyTime.ts`
pins `en-US`; `formatReleaseDate` has its own month names) and `<html lang>` is always
`en`.

1.1.0 makes the app translatable, ships 23 machine-drafted languages, lets anyone correct a
translation with a plain file edit, and adds a small accessibility follow-up on top of 9.4.

## 2. Scope

**In:**

- A translation layer for the desktop UI and the phone remote (§4), with a language setting
  (§5).
- Message catalogs, translator notes, a glossary and translation-status metadata (§6), with
  check/status/sync/review scripts (§7) and a volunteer workflow (§8).
- Locale-aware dates, numbers, durations, sorting and casing (§4.4).
- Fonts for every shipped script (§9).
- Rust-side text: tray menu, taskbar buttons, engine notices (§10).
- Accessibility follow-up (§12).

**Out:** right-to-left languages (Arabic, Hebrew, Persian, Urdu; needs a logical-property
layout audit) · Thai (needs word segmentation for line breaks) · translating TIDAL's own
content (titles, bios, editorial copy; see §10.4 for page titles) · translating error
*details* from Rust and TIDAL (§10.3) · installer (NSIS/WiX) languages · the Linux AT-SPI
issue (#10 in `plans/notes/2026-10-23-linux-bare-metal-run.md`; Linux stays WIP) ·
Weblate hosting itself (§8.3 keeps the door open).

## 4. Translation layer (UI)

### 4.1 Decisions

| # | Decision | Rationale |
|---|---|---|
| I18N-D1 | **Catalogs are JSON in ICU MessageFormat**, one file per language and namespace (§6). | The format Weblate, Crowdin and most translation tools import; handles plurals (Polish/Czech/Russian/Ukrainian have 3–4 forms), `select` and placeholders. |
| I18N-D2 | **Format with `intl-messageformat` (FormatJS)**, the one new runtime dependency; parsed messages are cached per language. No `svelte-i18n`. | A volunteer can write any valid ICU and it must work, so a hand-rolled subset parser is a liability. `svelte-i18n` is built on Svelte stores (AGENTS.md: runes only). |
| I18N-D3 | **English is bundled; other languages are lazy chunks** (`import()` per language, Vite code-splits them). | Boot loads one catalog; 23 languages × ~2,000 messages never sit in the main bundle. |
| I18N-D4 | **Keys are checked at compile time**: `t()` takes `MessageKey`, the key union of the English catalog (`resolveJsonModule`), so a typo fails `npm run check`. | Same guarantee the settings index has for its ids. |
| I18N-D5 | **Keys are semantic and dotted by area** (`settings.playback.crossfade.label`, `player.next`, `toast.linkCopied`), never the English text. | Changing English wording then shows as *stale* (§6.3) instead of silently dropping every translation. |
| I18N-D6 | **No string is built by concatenating translated fragments.** Whole sentences are messages with placeholders; plurals go through ICU `plural`. | Word order and grammar differ per language. |

### 4.2 Module

`ui/src/lib/i18n.svelte.ts`:

- `i18n.language` (`$state`, the resolved code), `i18n.setLanguage(code)` (loads the
  chunk, then flips the state, so text never shows a half-loaded language).
- `t(key, params?)` reads `i18n.language`, so every call in a template or `$derived`
  re-renders on a switch.
- A missing key in a non-English catalog falls back to English (the check script keeps that
  from shipping, §7.1); a missing English key is a type error.
- Plain-`.ts` code that builds text at module load (the settings index, sort labels, route
  titles, toasts) stores **keys**, and the text is produced through `t()` when it is shown.
  `lib/titles.ts` returns keyed titles; `SETTINGS_INDEX` entries carry `labelKey` /
  `sectionKey` / `keywordsKey`.

### 4.3 Boot

- `ui/index.html`'s first-frame script also reads the mirror `oxitide.language` (resolved
  code) and sets `<html lang>`, the same way theme/mode/tone are mirrored (`lib/theme.ts`).
- `main.ts` awaits that language's chunk before `mount` (English needs no await). The config
  (§5) stays the source of truth: `appearance.init`'s reconcile corrects the mirror and
  switches language if they differ.
- PM-D1: the boot scenarios are re-run (§13); a local chunk import is expected to cost a few
  ms.

### 4.4 Locale-aware formatting

All `Intl` calls take `i18n.language` (never `undefined`, which is the OS locale, and never a
hard-coded one):

- `historyTime.ts`: the clock time and the day label (`Today`/`Yesterday` become messages;
  the `en-US` pin goes).
- `format.ts`: `formatReleaseDate` → `Intl.DateTimeFormat` (`dateStyle: "medium"`; a
  year-only date stays the bare year); `formatCount` → `Intl.NumberFormat`
  (`notation: "compact"`); `formatListenTime` → `Intl.NumberFormat` unit style
  (`second`/`minute`/`hour`/`day`, `unitDisplay: "short"`) joined by a message pattern.
  `Intl.DurationFormat` is not used (WebKitGTK support is uncertain). `formatDuration`
  (`3:07` clock style) is unchanged.
- Sorting: `localeCompare` / `Intl.Collator` in `artistSort`, `albumSort`,
  `collectionSort`, `playlistSort`, `trackSort` take the active language.
- Casing: no `toUpperCase()` on translated text; small caps and label casing go through
  CSS `text-transform`, which follows `lang` (Turkish dotted İ, Greek accent removal).
- The Settings search (§4.5) folds case with `toLocaleLowerCase(language)`.

### 4.5 Settings search

Search matches the current language's labels and keywords **and** the English ones, so
English terms (ASIO, ReplayGain, crossfade) still find their row in any language. The
keyword messages are space-separated synonyms (their translator note says so). For CJK,
which has no spaces, matching is by substring on the whole query, as well as by token.

### 4.6 What stays English

Brand and product names (TIDAL, OxiTide, Hi-Fi Rack, AutoMix, CatJam, ASIO, WASAPI,
ReplayGain), quality names (Max, High, Low; `HI_RES_LOSSLESS` badges), codec and format
names, and keyboard key names. The glossary (§6.2) lists them as "do not translate".

**I18N-D7 — Rack legends:** the Hi-Fi Rack's panel legends (silkscreen-style labels) and
seven-segment/VFD readouts stay English, like real hi-fi hardware and because DSEG7 has no
glyphs beyond its segment set. Its accessible names, tooltips, menus and the pages inside
its display are translated. *Owner may overturn.*

## 5. Language setting

### 5.1 Config and command

- `[ui] language = "system"` (default) or a code from §3; unknown values load as `"system"`.
- New command `set_language(language: String)`: sync (a config writer; settings
  read-modify-write the whole config), listed in `generate_handler!`, `SYNC_COMMANDS` with
  that reason, and the phone remote's `NOT_EXPOSED` (desktop-only setting). It persists the
  choice and applies the shell text (§10.1). `api.ts` gains the field on `UiConfig`.

### 5.2 Resolution

The UI resolves `"system"` from `navigator.languages` (WebView2 and WebKitGTK follow the OS
display language) using §3's matching, and tells Rust the **resolved** code through
`set_shell_language(code)` (sync; `NOT_EXPOSED`; no persistence). Rust never resolves on its
own (no OS-locale crate): until the UI reports, the shell uses the saved explicit code, or
English for `"system"`. The tray menu is not visible before the window loads, so this gap is
not observable.

### 5.3 Picker

Settings → Appearance → **Language**: "System (Deutsch)" first, then every language by its
**endonym** (Deutsch, Français, 日本語, 简体中文, 繁體中文, Ελληνικά, Русский, Română,
Bahasa Indonesia…, from `locales/languages.json`, not `Intl.DisplayNames`), each tagged
with its status in the current UI language: *machine-translated*, *machine-translated,
cross-checked* (Chinese), or nothing once reviewed (§6.3). Below the picker a
**Help translate** link opens the translating guide (§8). Switching applies live (no
restart) and clears `viewCache` (cached pages hold formatted text only through `t()`, but
TIDAL page titles may change, §10.4).

## 6. Files

### 6.1 Layout

```
ui/src/locales/
  languages.json          code, endonym, status label, script (font stack, §9)
  glossary.json           term → per-language rendering, plus the do-not-translate list
  en/app.json             desktop UI (source of truth)
  en/remote.json          phone remote (loaded only by remote.html)
  en/shell.json           Rust-side text: tray, taskbar (plain strings, no ICU)
  notes/app.json …        one-line translator context per key ("Play" = button, verb)
  de/app.json …           one folder per language, same keys
  _meta/de/app.json …     per key: { status, source, draft }  (§6.3)
```

Namespaces are files, so the remote's bundle carries only `remote.json`, Rust embeds only
`shell.json` (§10.1), and a translation tool treats each as one component.

### 6.2 Glossary

`glossary.json` fixes one rendering per language for the core terms (Playlist, Album, Mix,
Radio, Queue, Collection, Favorites, Save for Later, Crossfade, Equalizer, Now Playing,
Track, Artist, Profile, Feed, Explore, Lyrics, Credits) and lists the names that are never
translated (§4.6). Drafts are made against it (§7.3), and the check script warns when a
message uses a glossary term's English source but not its rendering (warning, not error:
inflected forms differ).

### 6.3 Status metadata

For each translated key, `_meta/<lang>/<ns>.json` holds:

- `status`: `"machine"`, `"cross-checked"` or `"reviewed"`;
- `source`: a short hash (8 hex of SHA-256) of the English message it was translated from;
- `draft`: the same hash of the translation as last written by the drafting process.

From these the scripts derive each message's state:

| State | Rule |
|---|---|
| missing | key absent from the language file |
| stale | `source` ≠ hash of the current English |
| edited | `draft` ≠ hash of the current translation (a person changed it) |
| reviewed / cross-checked / machine | otherwise, from `status` |

A person's edit is never overwritten: drafting (§7.3) only writes **missing** and **stale**
messages that are not **edited**. A language's picker tag (§5.3) is its lowest status over
all messages.

## 7. Scripts (`scripts/i18n/`, Node, no network)

### 7.1 `check.mjs` (CI gate)

Fails on: a key missing from a language, a key not in English, ICU that does not parse,
placeholder or `plural`/`select` argument sets that differ from English, plural categories
missing for the language (`Intl.PluralRules(lang).resolvedOptions().pluralCategories`), ICU
in `shell.json`, a note missing for an English key, `_meta` naming a key that no longer
exists, and a `languages.json` entry without a folder (or the reverse). Warns on stale
messages and glossary misses. In `ci.yml` it and its `node --test` suite run in the `check`
job after the UI gates: both load the ICU parser from `ui/node_modules`, which only that job
installs.

### 7.2 `status.mjs`

Prints a table per language and namespace: % reviewed / cross-checked / machine / edited /
stale / missing. `--json` for the release gate note.

### 7.3 Drafting (no script calls a translation service)

Machine drafts are produced by agents in development sessions, never in CI and never at
runtime, so there is no API key and no network call in the build:

- The agent receives, per batch: the English messages, their notes, the glossary row for the
  language, and the existing translations of neighbouring keys (for consistency). It returns
  JSON, which `scripts/i18n/apply-draft.mjs <lang> <file>` writes into the catalog and
  `_meta` (status `machine`, fresh `source` and `draft` hashes), refusing **edited**
  messages.
- **Chinese (I18N-D8):** `zh-Hans` and `zh-Hant` are drafted by **DeepSeek V4.1 Flash**
  (OpenCode, `opencode-go/deepseek-v4.1-flash`), separately (Traditional is its own draft
  with Taiwan conventions, not a character conversion of Simplified: 软件/軟體, 视频/影片).
  Claude then reviews meaning and glossary use, and disagreements are resolved in a second
  pass; accepted messages get status `cross-checked`. Only UI text, notes and the glossary
  are sent (all public in the repository).
- **Every other language** is drafted by Claude.
- **Greek** is drafted like the rest; the owner reviews it with `review-sheet.mjs` (§7.5)
  and corrects in place, then `sync.mjs --review el` marks what was checked.

### 7.4 `sync.mjs`

After merging human edits: stamps every **edited** message as `reviewed` against the
current English (new `source` and `draft` hashes). `--review <lang> [--keys …]` marks
untouched messages reviewed after a full read-through. Run by the maintainer, never by CI.

### 7.5 `review-sheet.mjs <lang>`

Writes a side-by-side HTML sheet (key, English, note, translation, state) to a temp path
for reading a language end to end, grouped by area, stale and machine first.

### 7.6 `pseudo.mjs`

Generates a development-only pseudo-locale `en-XA` (accented and ~35% longer, wrapped in
`⟦ ⟧`) that is selectable in dev builds only. Any un-bracketed text on screen was not
extracted; anything clipped is an overflow bug.

## 8. Corrections and volunteers

### 8.1 Workflow

1. A volunteer edits `ui/src/locales/<lang>/<ns>.json` (GitHub's web editor is enough) and
   opens a pull request. No build tools; `_meta` is not touched.
2. CI runs `check.mjs`.
3. After merge, the maintainer runs `sync.mjs`, which marks those messages reviewed.

A new language is a new folder plus a `languages.json` row (and fonts if its script is new,
§9), in the same kind of PR.

### 8.2 Files to add

- `CONTRIBUTING.md` (none exists yet), section **Translating**: the file layout, ICU in five
  lines (placeholders, `plural`, `#`), the glossary, "keep placeholders and do not translate
  names", how to try a change (`npm --prefix ui run app:dev`, pick the language), and that
  machine drafts are expected to be wrong in places.
- `.github/ISSUE_TEMPLATE/translation.yml`: language, where in the app, current text,
  suggested text. For people who will not edit files.
- The Settings **Help translate** link (§5.3) points at the guide's section on GitHub.

### 8.3 Later: Weblate

The layout already fits Weblate's "JSON file" component format (one component per
namespace, `en` as the monolingual base, `notes/` as explanations). Connecting the hosted
libre plan is a later, owner-only step and changes no code; `_meta` stays the repository's
own (Weblate commits are "edited" to `sync.mjs`).

## 9. Fonts

The vendored Manrope and Inter are Latin-only subsets (`ui/src/styles/fonts.css`).

- Add their **latin-ext, Cyrillic(-ext) and Greek** subsets (from the same
  `@fontsource-variable` packages) as extra `@font-face` rules with `unicode-range`, so a
  subset downloads only when a page uses its characters. Covers Polish, Czech, Hungarian,
  Romanian (ș ț), Turkish, Ukrainian, Russian and Greek; Indonesian and the rest need only
  Latin. Licences (OFL) are already in `THIRD_PARTY_NOTICES.md`; the subset files are
  noted there.
- **CJK** is not bundled (megabytes). `--font-ui` and `--font-display` get per-language
  stacks under `:lang()` in `tokens.css`: Manrope/Inter first (Latin text in titles), then
  `ja`: Yu Gothic UI, Meiryo UI · `zh-Hans`: Microsoft YaHei UI · `zh-Hant`: Microsoft
  JhengHei UI · `ko`: Malgun Gothic · then the Linux Noto Sans CJK JP/SC/TC/KR, then
  `system-ui`. The correct `<html lang>` is what makes shared Han characters take the right
  regional shapes.
- CJK line breaking: `line-break: strict` for `ja`; `word-break: keep-all` for `ko`
  headings. The overflow pass (§13) covers truncation with ellipsis on CJK labels.

## 10. Rust side

### 10.1 Shell text

The tray menu (`tray.rs`: Show / Hide, Play / Pause, Next, Previous, Quit) and the taskbar
buttons (`thumbbar.rs`: Previous, Play, Pause, Next) read `shell.json`. Rust embeds every
language's `shell.json` with `include_str!` (a few KB in all), so translators edit one
catalog. A new `crates/oxitide-app/src/shell_text.rs` holds the lookup (falls back to English;
unit-tested), and `set_shell_language` rewrites the menu items' text (`MenuItem::set_text`)
and the next thumb-button tooltips. A Rust test asserts every embedded language has every
English key, and that the embedded set equals `languages.json`.

### 10.2 Engine notices

The few fixed output notices (device unavailable → default; exclusive unavailable → shared;
software volume compromises bit-perfect; output device disconnected; ASIO driver reset)
are matched in the UI by exact text to messages (`lib/engineNotices.ts`); an unknown or
composed notice is shown as today (English, `sentenceCase`). The wire and the Rust
constants are unchanged, so the Rust comparisons that rely on them keep working. A UI test
pins the table against the constants' text.

### 10.3 Errors

The ~190 commands return English `String` errors, and TIDAL's are `tidal error: …`. The UI
keeps its own translated sentence for the action ("Couldn't add to playlist") and shows the
error text as an English **detail** under it (or in the toast's details), not as the main
message. Translating error details is out of scope (§2); where a component today shows only
the raw error, it gains a translated headline.

### 10.4 TIDAL page titles

A spike (wiremock-backed, recorded in a note) checks whether TIDAL's pages endpoints honour
a `locale` query parameter for Home/Explore titles. If they do, `oxitide-tidal` passes the
resolved language on page requests only (and the page cache is cleared on a switch); if not,
the titles stay as TIDAL sends them. Section treatment never keys on titles (D-4 of the home
layout spec), so either way layout is unaffected.

## 12. Accessibility follow-up

9.4 closed the keyboard, focus, screen-reader-label and contrast criteria. 1.1.0 adds:

| # | Item | Detail |
|---|---|---|
| A-1 | **`lang` everywhere** | `<html lang>` follows the UI language (desktop and remote), so screen readers speak each language with the right voice. |
| A-2 | **Translated accessible names** | Every `aria-label`, `title`, live-region message (selection count in `TrackTable`, Sidebar announcements, buffering) and the skip link go through `t()` (part of extraction). |
| A-3 | **Windows contrast themes** (`forced-colors: active`) | No rules exist today. Focus rings become system-colour outlines; the seek and volume sliders, toggles, segmented controls, selected rows, the now-playing mark and drag targets stay visible with `Highlight`/`ButtonText`/`CanvasText`; inline Lucide icons use `currentColor`; decorative layers (backdrop, grain, dynamic colour, cover tints) are dropped. The Rack is usable but its skin is not preserved. |
| A-4 | **Track-change announcements** | A polite live region says "Now playing: {title} by {artists}" when the user starts or skips a track (play from a list, next, previous, queue jump). Automatic advances are not announced (no chatter during listening). |
| A-5 | **Interface zoom** | Settings → Appearance → **Zoom** (80–150 %, steps of 10) applied with the webview's zoom, persisted as `[ui] zoom`, plus Ctrl+= / Ctrl+− / Ctrl+0, listed in the shortcuts card. Layouts are checked at 150 % at the minimum window size. |

A-5 adds a command (`set_zoom`, sync config writer, `NOT_EXPOSED`). Visual changes from A-3
are recorded in `ui/design/DESIGN.md` (and the per-mode files where they differ).
