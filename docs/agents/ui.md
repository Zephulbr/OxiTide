# UI notes

Read before touching `ui/`: styling and modes, Hi-Fi Rack, Home/Explore/search, the page cache, name links, the queue glide, window chrome, drag and drop, and the easter eggs. Linked from `AGENTS.md`.

- Styling (Plan 10): design tokens live in `ui/src/styles/` — `tokens.css` (base + semantic token layers, motion, flags), `modes.css` (per-`data-mode` overrides), `fonts.css` (vendored Fraunces/Manrope/Inter). Components consume **semantic tokens only** (`--surface-*`, `--text`, `--accent`, …); never base or `--dyn-*` values directly. Appearance settings flow through `ui/src/lib/appearance.svelte.ts` (singleton `appearance`) → `data-mode`/`data-density` + CSS vars, persisted in the TOML config. Typography & layout and Dynamic color are per mode: the flat `[ui]` keys are the active mode's, and `set_ui_mode` (`UiConfig::switch_mode`) stashes them in `[ui.looks.<mode>]` and returns the next mode's `ModeLook`. Icons are inlined Lucide paths in `lib/components/Icon.svelte` — no unicode glyphs. WebKitGTK (Linux) re-runs every `backdrop-filter` on each composite, even `blur(0px)`: keep it off small repeated elements (16 mix-card badges held Home near 1 fps). It also presents every frame through the app's GTK main thread (~25% of a core at 60 fps for one small spinning element), so rAF loops that run for as long as playback does (discs, the now-playing mark, Rack meters) gate their draws through `lib/frameGate.ts` (`frameDue`; `gatedSpin` replaces a CSS spin), which draws at 30 fps on Linux, on one shared beat, and is a no-op elsewhere. On WebView2 every frame in which anything changes costs a frame of the whole page (main thread + compositor), however small the element: the now-playing mark turns as a stepped Web Animation (`steps(60)` per 2 s turn, 30 changes/s, so Chromium skips the frames between; 144 Hz rAF held ~1.4 Gcycles/s in Atmosphere, stepped ~0.36) and takes the gated loop only where `framesGated` (Linux) says so. Linux-only render fallbacks key off `data-platform="linux"`, set by `ui/index.html`'s first-frame script; profiling recipe in `docs/linux-build.md`. Covers render through `lib/components/Cover.svelte` + `lib/artwork.ts` (`coverUrl` builds `resources.tidal.com` URLs from the dashed UUID).
- Modes are `atmosphere` (default) / `instrument` / `rack` via `data-mode` on the root. `instrument` is labelled **Studio** in the UI (renamed 2026-10-23; the id stays) and has dark-only tones (`ui.instrument_tone` → `data-tone`: warm / neutral / black, in `modes.css`). Theme, mode and tone are mirrored to localStorage (`oxitide.theme` / `.mode` / `.tone`, `lib/theme.ts`) so the inline script in `ui/index.html` paints the first frame in the saved look; the config stays the source of truth and `appearance.init` rewrites the mirrors. Dynamic color flows `analyze_cover` (Rust, `artwork.rs` + pure `palette.rs`, cached in `cache/palettes.json`) → `--dyn-*` `@property` tokens. JS flag booleans live on `appearance` (`discSpin`, `waveSeek`, …) — components must not branch on mode. Design files: `ui/design/DESIGN.md` (shared foundation + index) and `ui/design/{atmosphere,instrument,rack}/DESIGN.md`; update them with any visual change.
- Hi-Fi Rack (Track 9.5, spec `2026-10-08-oxitide-track9-5-hifi-rack-design.md`): the one sanctioned shell branch is `App.svelte` mounting `ui/src/lib/rack/RackShell.svelte` (or `RackMini.svelte` in mini mode) from `appearance.rackShell`; pages render unmodified inside its display through `ui/src/lib/RoutedPage.svelte` (shared by both shells). Rack's private `--rack-*` tokens and its hardware skin live in `ui/src/styles/rack.css`, scoped to `[data-mode="rack"]` (skin rules under `:root[data-mode="rack"] .rack-main`); shared section containers carry the `pane` hook class. Options persist as `[rack]` (`set_rack_settings`); lamp colour is `--lamp-h/--lamp-c/--lamp-dim` written by `lib/rack/lamp.svelte.ts` (Rack ignores Dynamic color). DSP settings have one UI copy, `lib/dspStore.svelte.ts`, shared by Settings and the amp/EQ units. Meters read `crates/oxitide-audio/src/meter.rs` (`LevelTap`: read-only, `try_lock`, pushed after every `output.write`, disabled by default); `set_level_meter` starts/stops the 30 Hz `level_frame` emitter (`crates/oxitide-app/src/meter.rs`), driven by `lib/rack/levels.svelte.ts` only while a meter is mounted and the window is visible.
- Home (spec `2026-10-15-oxitide-home-redesign-design.md`) is a hero plus personal shelves, with TIDAL's editorial rows last. It is UI-only:
  - each shelf loads independently and hides when its source is empty or fails;
  - older history records hold names only, so `lib/homeSuggest.ts` resolves album/artist ids through a session-cached `getTrack`.
- Explore (spec `2026-10-16-oxitide-explore-redesign-design.md`): TIDAL's genre/mood/decade rows are artless page links. `PageItem.api_path` (only paths `pages::is_page_path` accepts) routes them to the `page` route (`views/TidalPage.svelte`, `get_page`), and `classifySection`'s `links` treatment draws them as name tiles (`PageLinkGrid.svelte`, `--link-wash-*` tokens). "New to you" (`lib/exploreSuggest.ts`) suggests unheard similar artists. Search results render through `SearchResultsView.svelte`: a top result (TIDAL's `topHit`, parsed leniently into `TopHit`, else `lib/searchResults.ts`'s exact-name artist fallback), a short track preview, and Home-style rows. The type chips page through `search_type` via `lib/searchPages.svelte.ts`. A typo that finds only its top hit (no tracks) searches again under the top hit's name (`searchCorrecting` in `lib/searchResults.ts`); the cache entry keeps the query its results answer, which paging uses. The search lives in the route (`{ name: "explore", q, kind }`, written with `nav.replace` once results settle; searches cached as `search:<query>` in `viewCache`), so Back from a result returns to the results.
- Page data cache: pages unmount on navigation, so Album, Artist, Mix, the Playlist header, Home and Explore load through `lib/viewCache.ts`. It is in memory and stale-while-revalidate: a cached value renders on the first frame, refetches in the background once older than its source's `freshMs` (default 60 s; 0 for user-edited or per-play data), and is not served past 30 min. It holds at most 80 entries (LRU) and is cleared on sign-in/out. Shared sources live in `lib/viewData.ts`; `MediaCard` prefetches the page a card opens after a 90 ms hover dwell (`prefetchRoute`). A cached value is applied synchronously, so a page's mount effect must call its load inside `untrack`. Otherwise the load's own reads and writes make the effect re-run forever (`effect_update_depth_exceeded`; it froze Artist). Writes must invalidate what they change: playlist edits go through `invalidatePlaylistCovers`, which also drops `playlist:<id>`. Track lists keep their own pager cache (`lib/pager.svelte.ts`).
- Name links (spec `2026-10-15-oxitide-name-links-design.md`): titles, albums and artists open their pages via `NameLink` / `ArtistLinks` / `QueueArtistLinks`. `QueueItem` (and `SessionItem`, `HistoryRecord`) carry optional `artist_refs` + `album_id`; items without them resolve on click through `lib/queueLinks.ts`. New `QueueItem` literals in Rust need both fields.
- Queue dock glide (`lib/queueTransition.ts`, addendum AR-9): the routed page is held at its final width while the rail animates, and that one layout change is FLIP-animated in step with it. Consequences:
  - width-driven layout must be **CSS** (container/media queries), not a ResizeObserver/`bind:clientWidth` count. A JS count lands a frame after the glide measures and makes the page jump mid-glide.
  - an element positioned from its own measurements (e.g. the Settings tab pill) re-places itself through `onPageResize`. The hook runs synchronously before the glide measures, and it must write the DOM directly.
  - the glide's fade-out copies are inert clones appended to `.main` and removed when it ends.
  - FLIP offsets are taken from each element's box on the glide's **first frame** (after the card width animations start), not from its final box: a resizing card re-flows its flex siblings and, through `aspect-ratio`, every section below, and an offset from the final box adds that layout motion on top (a first-frame jump, then the glide).
  - a box whose width animates must re-flow continuously inside. Clipping flex rows (carousels, the Explore chips) therefore snap and their items glide one by one: animated through, `flex-wrap` and `cqi`/container-query card counts step mid-glide.
- Window chrome: on Windows the main window is undecorated (`titlebar::install` in setup, before the first show); `WindowControls.svelte` draws the caption buttons and `lib/titlebar.ts` turns the top `--titlebar-h` band into the drag area. Snap Layouts work through a native child window over the HTML maximize button (`titlebar.rs`, positioned from the button's measured box via `set_snap_target`, `null` hides it in the mini player); the overlay owns the pointer there, so that button's hover/click arrive as `titlebar://snap` events. Linux keeps the system frame (`get_custom_titlebar` → false).
- Drag and drop (spec `2026-10-22-oxitide-drag-to-playlist-design.md`):
  - **One pointer-driven controller.** All drag and drop goes through
    `lib/dragDrop.svelte.ts`: `use:dragSource` (a payload getter) and `use:dropZone` (zones
    nest, and a zone returning a null verdict lets the one around it decide).
    - Never use HTML5 DnD; `dragDropEnabled` stays false.
    - Window listeners exist only from a press until it ends.
    - Attach zones to containers, not virtualized rows.
  - **Payloads** (`lib/dragPayload.ts`) carry rows, a track id, or a collection; tracks are
    fetched only on drop. Playlist targets come from `lib/playlistDrop.ts`. The queue rail
    inserts through `queue_insert`.
  - **Track tables multi-select through `lib/selection.svelte.ts`**, keyed by row object
    (playlists repeat ids). A drag from a selected row carries the selection.
- Easter eggs (spec `2026-10-21-oxitide-catjam-kuroneko-design.md`):
  - **CatJam:** `CatJam.svelte` sits on the player bar cover and bobs to the beat (not in the Rack or mini shells). Beats come **only from local analysis**: `crates/oxitide-audio/src/beat.rs` (`BeatTap`, read-only, pushed with the track's own frames before DSP) feeds `automix::analyze_beats` on the `oxitide-beat` helper, and the result is `EngineEvent::Beat` (desktop `beat` event). Never fetch tempo or beat data and never send track ids anywhere for it (the reference plugin sent every track id to a third-party API).
  - **Beat tracking is mount-driven:** `set_beat_tracking` is on only while CatJam is mounted. `AppState` re-applies it to an engine rebuilt after re-login.
  - **Output lead:** `Position` events carry `lead_ms`, the audio queued in the output and not yet heard (`AudioOutput::queued_ms`, smoothed by `output::LeadEstimate`, about 200–260 ms on WASAPI/ASIO; ALSA reports `snd_pcm_delay` after each write, ~530 ms through PipeWire). Anything synced to what is heard subtracts it.
  - **Sprite and coats:** the sprite is code (`lib/catjamSprite.ts` text grids; coats are palette swaps, `ui.catjam_coat`).
  - **Kuroneko and petting:** right-clicking oneko summons kuroneko (`Neko.svelte`, `oxitide:kuroneko`). Rubbing either cat (`lib/petting.ts`) floats hearts.
