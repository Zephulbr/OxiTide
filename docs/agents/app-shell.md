# App shell notes

Read before touching `crates/oxitide-app`: efficiency rules, the phone remote, the taskbar toolbar, persisted state files, Save for Later/collaborators, and distribution/updater. Linked from `AGENTS.md`.

- Efficiency rules (Track 13, spec `2026-10-16-oxitide-track13-efficiency-design.md`):
  - the queue is copy-on-write (`Arc<Vec>`) with a revision; `PlaybackState.queue` is not serialized, and the desktop `StateDto` carries it only when `queue_rev` moved (`get_playback_state` always does). The UI keeps its queue when a `state` event omits it. Code that needs the queue on every state must read `queue_rev`, not compare lists.
  - paused is idle: the worker parks on its condvar (no `Position` ticks), releases the output after `PAUSE_RELEASE` (30 s) and reopens the same spec on resume; UI loops (DiscArt, Rack meters/recorder) stop at rest, and the meter emitter goes quiet on silence.
  - output backends push through `oxitide-audio/src/ring.rs` (chunked writes, whole-frame underrun padding); keep per-sample work out of `write`. `stop` drops what is still buffered (~200 ms ring + the device buffer), so a natural end (queue end, a reopen for the next track's format) calls `AudioOutput::drain` first; user skips/seeks/errors stop at once. Underruns are counted per backend (`underruns()`) and tallied by the engine only during playback (`underrun_count`).
  - `webview_idle.rs` sets the WebView2 controller invisible + memory target Low while the main window is minimized or hidden to the tray.
  - the UI's `player.setVolume` coalesces to one call per frame and persists on release (`debounce` for wheel/key steps).
- Phone remote (Track 11, spec `2026-10-09-oxitide-track11-phone-remote-design.md`): `crates/oxitide-app/src/remote/` is an opt-in axum LAN server (`[remote]`, off by default; `AppState::remote` is `None` when off). Peers outside LAN/CGNAT ranges are dropped at accept; `Host` must be the arrival IP or loopback `localhost`; POSTs need JSON + `X-Oxi-Remote: 1`. Phones pair by QR (`#p=<token>`, single-use, 5 min) and get an `HttpOnly` cookie whose SHA-256 is stored in `config\remote.json`. `POST /api/rpc` dispatches through `remote/rpc.rs` — **an allowlist over the existing `commands::*` functions**; a test checks every `generate_handler!` entry is either in `ALLOWLIST` or `NOT_EXPOSED`, so a new command must be classified there. `GET /api/events` is SSE from `remote/events.rs` (slim `RemoteState`, never the queue; `queueRev` + `get_queue_page`), fed by one engine subscriber that returns at once with no client connected. The phone page is a second Vite entry (`ui/remote.html`, `ui/src/remote/`) that imports `lib/api.ts` **types only** and never `@tauri-apps/*` (guarded by `remote/imports.test.ts`); the server serves exact embedded-asset hits only (Tauri's resolver falls back to `index.html`) and proxies Vite in debug builds. Phone-supplied covers are limited to TIDAL images at the RPC boundary (they reach SMTC/Discord); favorite toggles from any surface go through `AppState::favorite_changed` (desktop `favorite_changed` event + SSE `favorite`); the phone uses Dynamic color via the allowlisted `analyze_cover` and the pure `lib/coverPalette.ts`.
- Taskbar thumbnail toolbar (spec `2026-10-16-oxitide-taskbar-thumbbar-design.md`): `thumbbar.rs` adds Previous / Play-Pause / Next under the Windows taskbar preview via `ITaskbarList3`, re-added on every `TaskbarButtonCreated` (Explorer restarts drop them). Clicks run `tray::run`; state comes from the engine subscriber as a `View` applied on the main thread (COM is apartment-bound). Glyphs are rasterized in Rust per DPI, so there are no icon assets.
- Track 10 state (all under `%APPDATA%\OxiTide\config\`): `session.rs` (queue/position/shuffle/repeat restore, `session.json`; logout parks it as `session.parked.json` tagged with the user id, and only that account's next login restores it, while another account's login deletes it), `history.rs` (`history.jsonl` + History/stats), `track_flags.rs` (content-blocking flags, `cache/track_flags.json`), `tray.rs` (tray menu/tooltip/close-to-tray, `ui.close_to_tray`), and `hotkeys.rs` (user-defined global accelerators via `tauri-plugin-global-shortcut`, `[hotkeys]`, empty defaults; once a chord is registered the global handler is the only delivery path). Ids in `session.json` and `history.jsonl` are written as V2 refs (`"tidal:<n>"`, `artist_refs` as `{ ref, name }`) through `stored_ref.rs` and read in either form; IPC payloads keep numbers, so a type that is both persisted and sent to the UI gets a file-only mirror (`history::StoredRecord`).
- Save for Later + Collaborators (spec `2026-10-22-oxitide-save-for-later-collaborators-design.md`):
  - **OxiTide's first writes on the public OpenAPI host.** `post_openapi` / `delete_openapi`
    in `client.rs` send `application/vnd.api+json` and one `Idempotency-Key` per write
    (resends repeat it).
  - **Save for Later:** `later.rs` uses `userCollectionSaveForLaters/me` and hydrates
    pages into the v1 models. The UI singleton `lib/later.svelte.ts` (like `trackFlags`)
    labels the menus. TIDAL stores a saved mix as a `playlists` reference with the mix
    id, so a non-UUID playlist id reads back as `LaterKind::Mix`. Videos are only
    counted.
  - **Invitations:** `shares.rs` creates COLLABORATOR shares and builds
    `tidal.com/playlist/{uuid}/invite?code=…` itself, because TIDAL returns no link.
    `AppState::invites` reuses one per playlist per session.
  - **Members** come from the internal v2 `user-playlists/{uuid}`. TIDAL can't revoke
    grants yet, so there is no "remove collaborator".
  - **Collaborator editing is not built yet.** `Playlist.owned` still means "creator";
    plan Task 1 settles it.
- Distribution (Track 12, spec `2026-10-13-oxitide-track12-distribution-design.md`, runbook `docs/release.md`): `.github/workflows/ci.yml` runs the Rust and UI gates on Windows + Ubuntu 22.04 (UI build first: `generate_context!` needs `ui/dist`); `release.yml` turns a `vX.Y.Z` tag into a **draft** release via `scripts/release/` (`check-version.mjs`, `make-manifest.mjs`; tests: `node --test scripts/release/release.test.mjs`). The version lives only in the workspace `Cargo.toml` (`[workspace.package]`): `tauri.conf.json` and `ui/package.json` carry none (Tauri falls back to Cargo's), and `check-version.mjs` fails if either gains one. The AUR recipe is a template (`packaging/aur/PKGBUILD.in`) that `make-pkgbuild.mjs` renders from the tag and attaches to the draft release. Updater artifacts come only from the `tauri.release.conf.json` overlay (so local `app:build` needs no key). Self-update lives in `crates/oxitide-app/src/updater.rs` (`tauri-plugin-updater`, called from Rust; thin commands in `commands.rs`, all `NOT_EXPOSED` to the phone remote; `[updates] check_on_start`). Windows shutdown work is `run_exit_work` in `main.rs` — the Windows updater ends the process without `RunEvent::Exit`, so install calls it first. The updater minisign key is not a code-signing certificate; Windows code signing is deferred.
