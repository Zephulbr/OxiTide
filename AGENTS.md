## Commands

Prereqs: Rust stable (`rust-toolchain.toml` pins it, with clippy/rustfmt), Node `^22.22.2 || ^24.15 || >=26` (jsdom 30's range; Node 20 breaks the UI tests; CI uses 24), and a one-time `npm --prefix ui install` (also installs the Tauri CLI locally).

- Dev run: `npm --prefix ui run app:dev` (starts Vite on port 1420, then the Tauri window).
  - `cargo run -p oxitide-app` is a trap: the debug build loads `devUrl` (http://localhost:1420) and fails with "localhost refused to connect" unless Vite is already running.
- Package installer: `npm --prefix ui run app:build` (NSIS per-user + MSI; artifacts under `target/release/bundle/`). Unsigned; WebView2 downloads at install time.
- Rust: `cargo test --workspace`; `cargo clippy --workspace -- -D warnings`. Single test: `cargo test -p oxitide-tidal <test_name>`.
- UI: `npm --prefix ui run check` (svelte-check); `npm --prefix ui test` (vitest). Single test: `npm --prefix ui test -- src/lib/format.test.ts`.
- Linux (WSL2 Ubuntu 22.04): environment, apt prerequisites, and build/package commands live in `docs/linux-build.md`; run the same `cargo test --workspace` and `cargo clippy --workspace -- -D warnings` gates there — they compile the `cfg(target_os = "linux")` code.

## Architecture

- `crates/oxitide-tidal` — pure async TIDAL API client (PKCE auth, token refresh, catalog/search/library/home). No Tauri/UI deps. All HTTP goes through `TidalClient::get` / `get_all_pages` in `client.rs`, which does single-flight refresh-on-401 and retries GETs up to 3 times on transport failures and 502–504 (writes retry only when the connection never opened); new endpoints should reuse it. Build the `reqwest::Client` with `oxitide_tidal::http_client()` (timeouts, 30 s idle-pool retirement, TCP keepalive — idle keep-alive sockets go stale during long tracks).
- Network resilience in `crates/oxitide-audio` (playback's retries all come from `retry::Backoff`; `connectivity::global()` reports OS network changes — Windows `NotifyNetworkConnectivityHintChange`, Linux a 2 s default-route check — which cut waits short, and time the OS reports offline does not count toward `retry::NETWORK_LIMIT`):
  - `fetch::download_ahead` writes a whole track to disk at full speed (the cache `.part`, or a `spill-*.part` scratch file for seeked streams) while a feeder hands it to the decoder through the 2 MB `StreamBuffer`; `AheadGate` lets only the first download in line run ahead (playing track before prefetch).
  - A lost network mid-track is ridden out **in place** (`fetch_recovering`): the segment retries on `Backoff::network`, rejected/aged links are renewed through a `fetch::Refresh` closure (same manifest hash and segment count, else `FetchRejected` and the engine restarts at the position), the decoder just waits, and the worker shows `PlaybackState.buffering` while it is starved — same session, same open device. A spent backoff is `NetworkLost` (not transient).
  - Failures before any audio (resolve errors, a stale failed prefetch) end the session; the worker waits on `Backoff::network` with `buffering` set and resumes at the recorded position (a pause during the wait keeps it).
  - Committed cache entries carry a `{entry}.fmp4.meta` sidecar (URL-free `StreamPlan`); `DiskCache::find_offline` plays a cached track when `playbackinfo` is unreachable (older entries without a sidecar via `decode::probe`). Startup restores offline from `config\tidal_session.json` when TIDAL is unreachable. Two non-v1 bases exist: internal `api.tidal.com/v2` (`get_v2`, used for writes/feed/folders) and public `openapi.tidal.com/v2` (`get_openapi`, JSON:API; playlist follower counts live only there).
- `crates/oxitide-app` — Tauri shell. New `#[tauri::command]` fns in `src/commands.rs` must also be listed in `generate_handler![...]` in `src/main.rs`, or the UI's `invoke` fails. A plain `#[tauri::command] pub fn` runs on the main thread; a test fails unless it is listed in `SYNC_COMMANDS` (commands.rs tests) with its reason. Blocking work that does not depend on call order goes in `#[tauri::command(async)]`; transport/queue commands and config writers stay sync (arrival order; settings read-modify-write the whole config).
- Efficiency rules (Track 13, spec `2026-10-16-oxitide-track13-efficiency-design.md`):
  - the queue is copy-on-write (`Arc<Vec>`) with a revision; `PlaybackState.queue` is not serialized, and the desktop `StateDto` carries it only when `queue_rev` moved (`get_playback_state` always does). The UI keeps its queue when a `state` event omits it. Code that needs the queue on every state must read `queue_rev`, not compare lists.
  - paused is idle: the worker parks on its condvar (no `Position` ticks), releases the output after `PAUSE_RELEASE` (30 s) and reopens the same spec on resume; UI loops (DiscArt, Rack meters/recorder) stop at rest, and the meter emitter goes quiet on silence.
  - output backends push through `oxitide-audio/src/ring.rs` (chunked writes, whole-frame underrun padding); keep per-sample work out of `write`.
  - `webview_idle.rs` sets the WebView2 controller invisible + memory target Low while the main window is minimized or hidden to the tray.
  - the UI's `player.setVolume` coalesces to one call per frame and persists on release (`debounce` for wheel/key steps).
- `ui/` — Svelte 5 runes only (`$state`, `$props`, `$effect`); no Svelte 4 stores or `export let`. Routing is a hand-rolled `Route` union in `ui/src/lib/nav.svelte.ts`, switched in `App.svelte`.
- Playback is implemented: `crates/oxitide-audio` holds the engine (queue, decode, cache, WASAPI output); `crates/oxitide-app/src/player.rs` wires it and maps DTOs. Plans 1–14 (playback, favorites, playlists, UX/data interaction, visual system, mini-player, integrations) and post-MVP Tracks 1–6 have shipped; Track 3 (performance) is complete (Phases A–D, 2026-10-02); Track 8 (Linux) shipped 2026-10-04; Track 10 (QoL) merged 2026-10-05. Sequencing and future tracks live in `docs/superpowers/specs/2026-09-24-oxitide-post-mvp-roadmap.md`.
- Styling (Plan 10): design tokens live in `ui/src/styles/` — `tokens.css` (base + semantic token layers, motion, flags), `modes.css` (per-`data-mode` overrides), `fonts.css` (vendored Fraunces/Manrope/Inter). Components consume **semantic tokens only** (`--surface-*`, `--text`, `--accent`, …); never base or `--dyn-*` values directly. Appearance settings flow through `ui/src/lib/appearance.svelte.ts` (singleton `appearance`) → `data-mode`/`data-density` + CSS vars, persisted in the TOML config. Icons are inlined Lucide paths in `lib/components/Icon.svelte` — no unicode glyphs. Covers render through `lib/components/Cover.svelte` + `lib/artwork.ts` (`coverUrl` builds `resources.tidal.com` URLs from the dashed UUID).
- Home (spec `2026-10-15-oxitide-home-redesign-design.md`) is a hero plus personal shelves, with TIDAL's editorial rows last. It is UI-only:
  - each shelf loads independently and hides when its source is empty or fails;
  - older history records hold names only, so `lib/homeSuggest.ts` resolves album/artist ids through a session-cached `getTrack`.
- Explore (spec `2026-10-16-oxitide-explore-redesign-design.md`): TIDAL's genre/mood/decade rows are artless page links. `PageItem.api_path` (only paths `pages::is_page_path` accepts) routes them to the `page` route (`views/TidalPage.svelte`, `get_page`), and `classifySection`'s `links` treatment draws them as name tiles (`PageLinkGrid.svelte`, `--link-wash-*` tokens). "New to you" (`lib/exploreSuggest.ts`) suggests unheard similar artists. Search results render through `SearchResultsView.svelte`: a top result (TIDAL's `topHit`, parsed leniently into `TopHit`, else `lib/searchResults.ts`'s exact-name artist fallback), a short track preview, and Home-style rows. The type chips page through `search_type` via `lib/searchPages.svelte.ts`. A typo that finds only its top hit (no tracks) searches again under the top hit's name (`searchCorrecting` in `lib/searchResults.ts`); the cache entry keeps the query its results answer, which paging uses. The search lives in the route (`{ name: "explore", q, kind }`, written with `nav.replace` once results settle; searches cached as `search:<query>` in `viewCache`), so Back from a result returns to the results.
- Page data cache: pages unmount on navigation, so Album, Artist, Mix, the Playlist header, Home and Explore load through `lib/viewCache.ts`. It is in memory and stale-while-revalidate: a cached value renders on the first frame, refetches in the background once older than its source's `freshMs` (default 60 s; 0 for user-edited or per-play data), and is not served past 30 min. It holds at most 80 entries (LRU) and is cleared on sign-in/out. Shared sources live in `lib/viewData.ts`; `MediaCard` prefetches the page a card opens after a 90 ms hover dwell (`prefetchRoute`). A cached value is applied synchronously, so a page's mount effect must call its load inside `untrack`. Otherwise the load's own reads and writes make the effect re-run forever (`effect_update_depth_exceeded`; it froze Artist). Writes must invalidate what they change: playlist edits go through `invalidatePlaylistCovers`, which also drops `playlist:<id>`. Track lists keep their own pager cache (`lib/pager.svelte.ts`).
- Name links (spec `2026-10-15-oxitide-name-links-design.md`): titles, albums and artists open their pages via `NameLink` / `ArtistLinks` / `QueueArtistLinks`. `QueueItem` (and `SessionItem`, `HistoryRecord`) carry optional `artist_refs` + `album_id`; items without them resolve on click through `lib/queueLinks.ts`. New `QueueItem` literals in Rust need both fields.
- Queue dock glide (`lib/queueTransition.ts`, addendum AR-9): the routed page is held at its final width while the rail animates, and that one layout change is FLIP-animated in step with it. Consequences:
  - width-driven layout must be **CSS** (container/media queries), not a ResizeObserver/`bind:clientWidth` count. A JS count lands a frame after the glide measures and makes the page jump mid-glide.
  - an element positioned from its own measurements (e.g. the Settings tab pill) re-places itself through `onPageResize`. The hook runs synchronously before the glide measures, and it must write the DOM directly.
  - the glide's fade-out copies are inert clones appended to `.main` and removed when it ends.
- App icon: SVG sources in `crates/oxitide-app/icons/svg/` (size-specific variants of one mark; `ui/public/favicon.svg` is a copy of `icon-64.svg`). Never hand-edit the PNG/ICO files in `icons/` — run `node scripts/icons/build-icons.mjs` to regenerate them.
- Window chrome: on Windows the main window is undecorated (`titlebar::install` in setup, before the first show); `WindowControls.svelte` draws the caption buttons and `lib/titlebar.ts` turns the top `--titlebar-h` band into the drag area. Snap Layouts work through a native child window over the HTML maximize button (`titlebar.rs`, positioned from the button's measured box via `set_snap_target`, `null` hides it in the mini player); the overlay owns the pointer there, so that button's hover/click arrive as `titlebar://snap` events. Linux keeps the system frame (`get_custom_titlebar` → false).
- Modes are `atmosphere` (default) / `instrument` / `rack` via `data-mode` on the root. Dynamic color flows `analyze_cover` (Rust, `artwork.rs` + pure `palette.rs`, cached in `cache/palettes.json`) → `--dyn-*` `@property` tokens. JS flag booleans live on `appearance` (`discSpin`, `waveSeek`, …) — components must not branch on mode. Design files: `ui/design/DESIGN.md` (shared foundation + index) and `ui/design/{atmosphere,instrument,rack}/DESIGN.md`; update them with any visual change.
- Hi-Fi Rack (Track 9.5, spec `2026-10-08-oxitide-track9-5-hifi-rack-design.md`): the one sanctioned shell branch is `App.svelte` mounting `ui/src/lib/rack/RackShell.svelte` (or `RackMini.svelte` in mini mode) from `appearance.rackShell`; pages render unmodified inside its display through `ui/src/lib/RoutedPage.svelte` (shared by both shells). Rack's private `--rack-*` tokens and its hardware skin live in `ui/src/styles/rack.css`, scoped to `[data-mode="rack"]` (skin rules under `:root[data-mode="rack"] .rack-main`); shared section containers carry the `pane` hook class. Options persist as `[rack]` (`set_rack_settings`); lamp colour is `--lamp-h/--lamp-c/--lamp-dim` written by `lib/rack/lamp.svelte.ts` (Rack ignores Dynamic color). DSP settings have one UI copy, `lib/dspStore.svelte.ts`, shared by Settings and the amp/EQ units. Meters read `crates/oxitide-audio/src/meter.rs` (`LevelTap`: read-only, `try_lock`, pushed after every `output.write`, disabled by default); `set_level_meter` starts/stops the 30 Hz `level_frame` emitter (`crates/oxitide-app/src/meter.rs`), driven by `lib/rack/levels.svelte.ts` only while a meter is mounted and the window is visible.
- ASIO output (Track 7, spec `2026-10-11-oxitide-track7-asio-output-design.md`): Windows `real_output()` is `routed_output::RoutedOutput`, which dispatches to `WasapiOutput` or `AsioOutput` by device id (`asio:<registry key>`; drivers enumerate from `HKLM\SOFTWARE\ASIO` without loading). The IASIO binding is hand-written in `asio_sys.rs` (no `asio-sys`/LLVM; 64-bit only). An `asio:` device always runs `OutputMode::Exclusive` (`output::effective_mode`); a failed ASIO open follows `exclusive_fallback` (WASAPI shared default + notice, or error). Driver calls stay on the `oxitide-asio` owner thread; the render callback reads a process-global state, so only one ASIO driver can be open.
- Sound processing (Track 7): `crates/oxitide-audio/src/dsp.rs` (pure: `DspSettings`, RBJ `f64` biquads, ReplayGain math, crossfade `Tail`) runs in the playback worker between the producer and `output.write`. Identity settings must stay a no-op so exclusive `i32` output remains sample-exact; any stage that alters samples clears `PlaybackState.bit_perfect` and lists itself in `dsp_stages` (never in the output notice). Settings apply live via `Engine::set_dsp` (version counter, no restart), persist as `[dsp]`, and reach the engine through `set_dsp_settings`. Crossfade holds back a FIFO of decoded audio and mixes it into the prefetched next stream on natural ends only. AutoMix (Track 7b, `automix.rs`, pure Rust: `rustfft` + `rubato`) adds individually toggled silence trim, cross-format overlap, and beat matching: the prefetch stream pre-reads the next track's opening (`TrackStream.pending`), beat analysis runs on a helper thread while the tail keeps playing, and every transition publishes `PlaybackState.last_transition`. With the toggles off the Track 7 path is unchanged. Track 7b.2 adds `CrossfadeSettings.style` (`classic` / `quick` / `blend` / `auto` — Auto picks per pair from `automix::TransitionFeatures`, logged with every AutoMix transition; `dsp::MixShape` carries the curve, incl. the bass swap, into `Tail`) and a replay lab: while AutoMix is on the engine keeps the last tail + head (with ReplayGain, before EQ) in memory (`Engine::render_last_transition`), and the `automix_render` command returns `[u32 header len][JSON][WAV]` that Settings plays via a `blob:` URL (CSP `media-src`) — never written to disk. In shared mode with AutoMix on, a natural advance keeps the open device across format changes and streams a different rate through `dsp::StreamResampler` (AM-D16); long tail writes go through `write_responsive` (sliced, so transport commands act, and it feeds the level meter).
- Phone remote (Track 11, spec `2026-10-09-oxitide-track11-phone-remote-design.md`): `crates/oxitide-app/src/remote/` is an opt-in axum LAN server (`[remote]`, off by default; `AppState::remote` is `None` when off). Peers outside LAN/CGNAT ranges are dropped at accept; `Host` must be the arrival IP or loopback `localhost`; POSTs need JSON + `X-Oxi-Remote: 1`. Phones pair by QR (`#p=<token>`, single-use, 5 min) and get an `HttpOnly` cookie whose SHA-256 is stored in `config\remote.json`. `POST /api/rpc` dispatches through `remote/rpc.rs` — **an allowlist over the existing `commands::*` functions**; a test checks every `generate_handler!` entry is either in `ALLOWLIST` or `NOT_EXPOSED`, so a new command must be classified there. `GET /api/events` is SSE from `remote/events.rs` (slim `RemoteState`, never the queue; `queueRev` + `get_queue_page`), fed by one engine subscriber that returns at once with no client connected. The phone page is a second Vite entry (`ui/remote.html`, `ui/src/remote/`) that imports `lib/api.ts` **types only** and never `@tauri-apps/*` (guarded by `remote/imports.test.ts`); the server serves exact embedded-asset hits only (Tauri's resolver falls back to `index.html`) and proxies Vite in debug builds. Phone-supplied covers are limited to TIDAL images at the RPC boundary (they reach SMTC/Discord); favorite toggles from any surface go through `AppState::favorite_changed` (desktop `favorite_changed` event + SSE `favorite`); the phone uses Dynamic color via the allowlisted `analyze_cover` and the pure `lib/coverPalette.ts`.
- Taskbar thumbnail toolbar (spec `2026-10-16-oxitide-taskbar-thumbbar-design.md`): `thumbbar.rs` adds Previous / Play-Pause / Next under the Windows taskbar preview via `ITaskbarList3`, re-added on every `TaskbarButtonCreated` (Explorer restarts drop them). Clicks run `tray::run`; state comes from the engine subscriber as a `View` applied on the main thread (COM is apartment-bound). Glyphs are rasterized in Rust per DPI, so there are no icon assets.
- Drag and drop (spec `2026-10-22-oxitide-drag-to-playlist-design.md`):
  - **One pointer-driven controller.** All drag and drop goes through
    `lib/dragDrop.svelte.ts`: `use:dragSource` (a payload getter) and `use:dropZone` (zones
    nest, and a zone returning a null verdict lets the one around it decide).
    - Never use HTML5 DnD; `dragDropEnabled` stays false.
    - Window listeners exist only from a press until it ends.
    - Attach zones to containers, not virtualized rows.
  - **Payloads** (`lib/dragPayload.ts`) carry rows, a track id, or a collection; tracks are
    fetched only on drop. Playlist targets come from `lib/playlistDrop.ts`. The queue rail
    inserts through `queue_insert`.
  - **Track tables multi-select through `lib/selection.svelte.ts`**, keyed by row object
    (playlists repeat ids). A drag from a selected row carries the selection.
- Save for Later + Collaborators (spec `2026-10-22-oxitide-save-for-later-collaborators-design.md`):
  - **OxiTide's first writes on the public OpenAPI host.** `post_openapi` / `delete_openapi`
    in `client.rs` send `application/vnd.api+json` and one `Idempotency-Key` per write
    (resends repeat it).
  - **Save for Later:** `later.rs` uses `userCollectionSaveForLaters/me` and hydrates
    pages into the v1 models. The UI singleton `lib/later.svelte.ts` (like `trackFlags`)
    labels the menus. TIDAL stores a saved mix as a `playlists` reference with the mix
    id, so a non-UUID playlist id reads back as `LaterKind::Mix`. Videos are only
    counted.
  - **Invitations:** `shares.rs` creates COLLABORATOR shares and builds
    `tidal.com/playlist/{uuid}/invite?code=…` itself, because TIDAL returns no link.
    `AppState::invites` reuses one per playlist per session.
  - **Members** come from the internal v2 `user-playlists/{uuid}`. TIDAL can't revoke
    grants yet, so there is no "remove collaborator".
  - **Collaborator editing is not built yet.** `Playlist.owned` still means "creator";
    plan Task 1 settles it.
- Easter eggs (spec `2026-10-21-oxitide-catjam-kuroneko-design.md`):
  - **CatJam:** `CatJam.svelte` sits on the player bar cover and bobs to the beat (not in the Rack or mini shells). Beats come **only from local analysis**: `crates/oxitide-audio/src/beat.rs` (`BeatTap`, read-only, pushed with the track's own frames before DSP) feeds `automix::analyze_beats` on the `oxitide-beat` helper, and the result is `EngineEvent::Beat` (desktop `beat` event). Never fetch tempo or beat data and never send track ids anywhere for it (the reference plugin sent every track id to a third-party API).
  - **Beat tracking is mount-driven:** `set_beat_tracking` is on only while CatJam is mounted. `AppState` re-applies it to an engine rebuilt after re-login.
  - **Output lead:** `Position` events carry `lead_ms`, the audio queued in the output and not yet heard (`AudioOutput::queued_ms`, smoothed by `output::LeadEstimate`, about 200–260 ms on WASAPI/ASIO). Anything synced to what is heard subtracts it. ALSA reports none yet.
  - **Sprite and coats:** the sprite is code (`lib/catjamSprite.ts` text grids; coats are palette swaps, `ui.catjam_coat`).
  - **Kuroneko and petting:** right-clicking oneko summons kuroneko (`Neko.svelte`, `oxitide:kuroneko`). Rubbing either cat (`lib/petting.ts`) floats hearts.
- Track 10 state (all under `%APPDATA%\OxiTide\config\`): `session.rs` (queue/position/shuffle/repeat restore, `session.json`), `history.rs` (`history.jsonl` + History/stats), `track_flags.rs` (content-blocking flags, `cache/track_flags.json`), `tray.rs` (tray menu/tooltip/close-to-tray, `ui.close_to_tray`), and `hotkeys.rs` (user-defined global accelerators via `tauri-plugin-global-shortcut`, `[hotkeys]`, empty defaults; once a chord is registered the global handler is the only delivery path).

- Distribution (Track 12, spec `2026-10-13-oxitide-track12-distribution-design.md`, runbook `docs/release.md`): `.github/workflows/ci.yml` runs the Rust and UI gates on Windows + Ubuntu 22.04 (UI build first: `generate_context!` needs `ui/dist`); `release.yml` turns a `vX.Y.Z` tag into a **draft** release via `scripts/release/` (`check-version.mjs`, `make-manifest.mjs`; tests: `node --test scripts/release/release.test.mjs`). The version lives only in the workspace `Cargo.toml` (`[workspace.package]`): `tauri.conf.json` and `ui/package.json` carry none (Tauri falls back to Cargo's), and `check-version.mjs` fails if either gains one. Updater artifacts come only from the `tauri.release.conf.json` overlay (so local `app:build` needs no key). Self-update lives in `crates/oxitide-app/src/updater.rs` (`tauri-plugin-updater`, called from Rust; thin commands in `commands.rs`, all `NOT_EXPOSED` to the phone remote; `[updates] check_on_start`). Windows shutdown work is `run_exit_work` in `main.rs` — the Windows updater ends the process without `RunEvent::Exit`, so install calls it first. The updater minisign key is not a code-signing certificate; Windows code signing is deferred.

## IPC contract

- `invoke` sends camelCase args; Rust params stay snake_case (`redirect_url` ↔ `redirectUrl`).
- Payload field names are inconsistent and driven by serde attributes (`Track.audioQuality` is renamed, `HomeItem.item_type` is verbatim). Rust DTOs are the source of truth — keep `ui/src/lib/api.ts` interfaces in sync by hand.
- The phone remote's RPC mirrors `invoke`: `{method, params}` with camelCase params mapped onto snake_case in `remote/rpc.rs`; errors are `"<code>: <message>"`. Its wire types (`RemoteState`, `RemoteQueuePage`, …) are camelCase and mirrored in `api.ts` like any DTO.
- Auth is PKCE with a browser + paste-back redirect (no embedded webview); `auth_restore` silently refreshes on startup.

## Testing / security quirks

- HTTP tests use `wiremock` and must never hit the live TIDAL API.
- Tokens live in Windows Credential Manager via `KeyringStore` (service `oxitide`, user `tidal`); unit tests must use `MemoryStore`. Never log token values (`TokenSet` has a redacting `Debug` impl). Track 8 adds a Linux backend; note that keyring v3 silently falls back to its mock store if no platform feature is enabled.
- GUI smoke checks require a human, a real account, and a browser login; record them as checklists in `docs/superpowers/plans/notes/`.
- Component tests are jsdom per file (`// @vitest-environment jsdom`) via `@testing-library/svelte`; pure-logic tests stay on node. Modal focus handling lives in `lib/focusTrap.ts`, `lib/portal.ts` and `lib/dialogs.svelte.ts`; route titles in `lib/titles.ts` (with the skip link in `App.svelte`).

## Performance harness

Track 3's measurement gate lives in `scripts/perf/` (manual; no CI):

- Windows-only exemption (Track 8, T8-D3): the scripted runner/driver (`run-scenario.ps1`, `drive.mjs`) speaks the WebView2 CDP endpoint and is not ported to WebKitGTK. On Linux the `/proc` metrics in `crates/oxitide-app/src/perf.rs` keep process-relative marks, memory, and playback rows measurable via `OXITIDE_PERF_SCENARIO` + `node scripts/perf/check.mjs`; frame/interaction budgets stay unmeasured until the deferred harness port. Authority: `docs/superpowers/plans/notes/2026-10-03-track8-perf-exemption.md`.
- `powershell -ExecutionPolicy Bypass -File scripts/perf/run-scenario.ps1 -Scenario <S1..S10> [-Runs n] [-Manual] [-SkipCheck] [-Minutes n]` — launches the debug exe (Vite must be warm; the script starts it if port 1420 is free) and drives the scenario over the WebView2 CDP endpoint. Raw JSONL lands in the gitignored `.superpowers/perf/runs/`.
  - `-Release` (Track 13) runs `target/release/oxitide-app.exe` with the UI embedded and no Vite; build it with `npm --prefix ui run app:build:perf` (`tauri build --no-bundle`; plain `cargo build --release` still points at `devUrl`). Baselines are taken on release builds.
  - Runs end through `perf_quit` (normal exit work); the runner kills the app only if it is still up 10 s later.
- `node scripts/perf/check.mjs` (or `npm --prefix ui run perf:check`) aggregates the corpus against `scripts/perf/budgets.json` (mirrors spec §4.2) and exits non-zero on any breach. Samples carry per-process working set, private bytes and cumulative CPU ms, plus `ipc` rows (cumulative desktop `playback_event` + Rack `level_frame` count/bytes; rates are last − first, never a sum of rows); the checker derives `cpu_app_pct`, `cpu_webview_pct` (percent of **one core**), `private_max_mb`, `ipc_events_per_min`, `ipc_kb_per_min`, measured from a `measure_start` mark when the driver sets one.
  - A budget is checked against the worst run (p95 across runs), a `min` budget against the lowest; `"of": "median"` checks the median run instead. CPU and IPC rate rows use it (they swing between runs; the S11–S14 budgets are median + 15 %, CPU at least +0.5 pt), memory and frame rows stay worst-run.
- Scenarios: S1 cold start, S2 warm start, S3-miss/S3-hit TTFS, S4 gapless advance, S5-instrument/S5-atmosphere scroll, S6 10k filter/sort/album, S7 10k queue load (end to end: command → state applied in the UI), S8 cache loop, S9 2 h soak, S10 manual stability, and (Track 13) S11 idle paused, S12 playing hidden to tray (owner closes the window when prompted), S13 Rack with meters, S14 volume drag on a 10k queue. S4/S8/S9/S10/S12 are human-in-the-loop (real account/audio); the rest are scripted. S7/S14 replace the session queue with synthetic items and clear it afterwards.
- `drive.mjs`'s `awaitPlaying` requires the position to advance: a session stuck paused at a restored position reports `playing` with a non-zero position, and silent runs used to be measured as playing. Check `first_pcm` rows before trusting a playback scenario.
- Conditions matter: single app, foreground, Vite warm, no deliberate background load. The current budgets and the S4 documented finding are recorded in `docs/superpowers/plans/notes/2026-10-02-track3-phase-d.md`; Track 13's release-build results and the S11–S14 budgets in `docs/superpowers/plans/notes/2026-10-19-track13-perf-results.md`.

## Workflow

- Feature work is spec'd/planned as dated files in `docs/superpowers/specs/` and `docs/superpowers/plans/`; extend that series instead of inventing new structure. `.superpowers/` is gitignored brainstorm/session state.
- Legal/security surface: root `LICENSE` (AGPL-3.0-or-later) and `THIRD_PARTY_NOTICES.md`; the webview CSP lives in `crates/oxitide-app/tauri.conf.json` (`csp` + `devCsp`) — update the allowlist when adding a remote origin.
- Windows-first: `keyring` uses `windows-native` on Windows; non-Windows builds use output/media/scheme stubs until Track 8 (Linux support).
