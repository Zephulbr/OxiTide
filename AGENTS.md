## Commands

Prereqs: Rust stable (`rust-toolchain.toml` pins it, with clippy/rustfmt), Node 20+, and a one-time `npm --prefix ui install` (also installs the Tauri CLI locally).

- Dev run: `npm --prefix ui run app:dev` (starts Vite on port 1420, then the Tauri window).
  - `cargo run -p oxitide-app` is a trap: the debug build loads `devUrl` (http://localhost:1420) and fails with "localhost refused to connect" unless Vite is already running.
- Package installer: `npm --prefix ui run app:build` (NSIS per-user + MSI; artifacts under `target/release/bundle/`). Unsigned; WebView2 downloads at install time.
- Rust: `cargo test --workspace`; `cargo clippy --workspace -- -D warnings`. Single test: `cargo test -p oxitide-tidal <test_name>`.
- UI: `npm --prefix ui run check` (svelte-check); `npm --prefix ui test` (vitest). Single test: `npm --prefix ui test -- src/lib/format.test.ts`.
- Linux (WSL2 Ubuntu 22.04): environment, apt prerequisites, and build/package commands live in `docs/linux-build.md`; run the same `cargo test --workspace` and `cargo clippy --workspace -- -D warnings` gates there — they compile the `cfg(target_os = "linux")` code.

## Architecture

- `crates/oxitide-tidal` — pure async TIDAL API client (PKCE auth, token refresh, catalog/search/library/home). No Tauri/UI deps. All HTTP goes through `TidalClient::get` / `get_all_pages` in `client.rs`, which does single-flight refresh-on-401; new endpoints should reuse it. Two non-v1 bases exist: internal `api.tidal.com/v2` (`get_v2`, used for writes/feed/folders) and public `openapi.tidal.com/v2` (`get_openapi`, JSON:API; playlist follower counts live only there).
- `crates/oxitide-app` — Tauri shell. New `#[tauri::command]` fns in `src/commands.rs` must also be listed in `generate_handler![...]` in `src/main.rs`, or the UI's `invoke` fails.
- `ui/` — Svelte 5 runes only (`$state`, `$props`, `$effect`); no Svelte 4 stores or `export let`. Routing is a hand-rolled `Route` union in `ui/src/lib/nav.svelte.ts`, switched in `App.svelte`.
- Playback is implemented: `crates/oxitide-audio` holds the engine (queue, decode, cache, WASAPI output); `crates/oxitide-app/src/player.rs` wires it and maps DTOs. Plans 1–14 (playback, favorites, playlists, UX/data interaction, visual system, mini-player, integrations) and post-MVP Tracks 1–6 have shipped; Track 3 (performance) is complete (Phases A–D, 2026-10-02); Track 8 (Linux) shipped 2026-10-04; Track 10 (QoL) merged 2026-10-05. Sequencing and future tracks live in `docs/superpowers/specs/2026-09-24-oxitide-post-mvp-roadmap.md`.
- Styling (Plan 10): design tokens live in `ui/src/styles/` — `tokens.css` (base + semantic token layers, motion, flags), `modes.css` (per-`data-mode` overrides), `fonts.css` (vendored Fraunces/Manrope/Inter). Components consume **semantic tokens only** (`--surface-*`, `--text`, `--accent`, …); never base or `--dyn-*` values directly. Appearance settings flow through `ui/src/lib/appearance.svelte.ts` (singleton `appearance`) → `data-mode`/`data-density` + CSS vars, persisted in the TOML config. Icons are inlined Lucide paths in `lib/components/Icon.svelte` — no unicode glyphs. Covers render through `lib/components/Cover.svelte` + `lib/artwork.ts` (`coverUrl` builds `resources.tidal.com` URLs from the dashed UUID).
- App icon: SVG sources in `crates/oxitide-app/icons/svg/` (size-specific variants of one mark; `ui/public/favicon.svg` is a copy of `icon-64.svg`). Never hand-edit the PNG/ICO files in `icons/` — run `node scripts/icons/build-icons.mjs` to regenerate them.
- Window chrome: on Windows the main window is undecorated (`titlebar::install` in setup, before the first show); `WindowControls.svelte` draws the caption buttons and `lib/titlebar.ts` turns the top `--titlebar-h` band into the drag area. Snap Layouts work through a native child window over the HTML maximize button (`titlebar.rs`, positioned from the button's measured box via `set_snap_target`, `null` hides it in the mini player); the overlay owns the pointer there, so that button's hover/click arrive as `titlebar://snap` events. Linux keeps the system frame (`get_custom_titlebar` → false).
- Modes are `atmosphere` (default) / `instrument` / `rack` via `data-mode` on the root. Dynamic color flows `analyze_cover` (Rust, `artwork.rs` + pure `palette.rs`, cached in `cache/palettes.json`) → `--dyn-*` `@property` tokens. JS flag booleans live on `appearance` (`discSpin`, `waveSeek`, …) — components must not branch on mode. Design files: `ui/design/DESIGN.md` (shared foundation + index) and `ui/design/{atmosphere,instrument,rack}/DESIGN.md`; update them with any visual change.
- Hi-Fi Rack (Track 9.5, spec `2026-10-08-oxitide-track9-5-hifi-rack-design.md`): the one sanctioned shell branch is `App.svelte` mounting `ui/src/lib/rack/RackShell.svelte` (or `RackMini.svelte` in mini mode) from `appearance.rackShell`; pages render unmodified inside its display through `ui/src/lib/RoutedPage.svelte` (shared by both shells). Rack's private `--rack-*` tokens and its hardware skin live in `ui/src/styles/rack.css`, scoped to `[data-mode="rack"]` (skin rules under `:root[data-mode="rack"] .rack-main`); shared section containers carry the `pane` hook class. Options persist as `[rack]` (`set_rack_settings`); lamp colour is `--lamp-h/--lamp-c/--lamp-dim` written by `lib/rack/lamp.svelte.ts` (Rack ignores Dynamic color). DSP settings have one UI copy, `lib/dspStore.svelte.ts`, shared by Settings and the amp/EQ units. Meters read `crates/oxitide-audio/src/meter.rs` (`LevelTap`: read-only, `try_lock`, pushed after every `output.write`, disabled by default); `set_level_meter` starts/stops the 30 Hz `level_frame` emitter (`crates/oxitide-app/src/meter.rs`), driven by `lib/rack/levels.svelte.ts` only while a meter is mounted and the window is visible.
- ASIO output (Track 7, spec `2026-10-11-oxitide-track7-asio-output-design.md`): Windows `real_output()` is `routed_output::RoutedOutput`, which dispatches to `WasapiOutput` or `AsioOutput` by device id (`asio:<registry key>`; drivers enumerate from `HKLM\SOFTWARE\ASIO` without loading). The IASIO binding is hand-written in `asio_sys.rs` (no `asio-sys`/LLVM; 64-bit only). An `asio:` device always runs `OutputMode::Exclusive` (`output::effective_mode`); a failed ASIO open follows `exclusive_fallback` (WASAPI shared default + notice, or error). Driver calls stay on the `oxitide-asio` owner thread; the render callback reads a process-global state, so only one ASIO driver can be open.
- Sound processing (Track 7): `crates/oxitide-audio/src/dsp.rs` (pure: `DspSettings`, RBJ `f64` biquads, ReplayGain math, crossfade `Tail`) runs in the playback worker between the producer and `output.write`. Identity settings must stay a no-op so exclusive `i32` output remains sample-exact; any stage that alters samples clears `PlaybackState.bit_perfect` and lists itself in `dsp_stages` (never in the output notice). Settings apply live via `Engine::set_dsp` (version counter, no restart), persist as `[dsp]`, and reach the engine through `set_dsp_settings`. Crossfade holds back a FIFO of decoded audio and mixes it into the prefetched next stream on natural ends only. AutoMix (Track 7b, `automix.rs`, pure Rust: `rustfft` + `rubato`) adds individually toggled silence trim, cross-format overlap, and beat matching: the prefetch stream pre-reads the next track's opening (`TrackStream.pending`), beat analysis runs on a helper thread while the tail keeps playing, and every transition publishes `PlaybackState.last_transition`. With the toggles off the Track 7 path is unchanged. Track 7b.2 adds `CrossfadeSettings.style` (`classic` / `quick` / `blend` / `auto` — Auto picks per pair from `automix::TransitionFeatures`, logged with every AutoMix transition; `dsp::MixShape` carries the curve, incl. the bass swap, into `Tail`) and a replay lab: while AutoMix is on the engine keeps the last tail + head (with ReplayGain, before EQ) in memory (`Engine::render_last_transition`), and the `automix_render` command returns `[u32 header len][JSON][WAV]` that Settings plays via a `blob:` URL (CSP `media-src`) — never written to disk. In shared mode with AutoMix on, a natural advance keeps the open device across format changes and streams a different rate through `dsp::StreamResampler` (AM-D16); long tail writes go through `write_responsive` (sliced, so transport commands act, and it feeds the level meter).
- Phone remote (Track 11, spec `2026-10-09-oxitide-track11-phone-remote-design.md`): `crates/oxitide-app/src/remote/` is an opt-in axum LAN server (`[remote]`, off by default; `AppState::remote` is `None` when off). Peers outside LAN/CGNAT ranges are dropped at accept; `Host` must be the arrival IP or loopback `localhost`; POSTs need JSON + `X-Oxi-Remote: 1`. Phones pair by QR (`#p=<token>`, single-use, 5 min) and get an `HttpOnly` cookie whose SHA-256 is stored in `config\remote.json`. `POST /api/rpc` dispatches through `remote/rpc.rs` — **an allowlist over the existing `commands::*` functions**; a test checks every `generate_handler!` entry is either in `ALLOWLIST` or `NOT_EXPOSED`, so a new command must be classified there. `GET /api/events` is SSE from `remote/events.rs` (slim `RemoteState`, never the queue; `queueRev` + `get_queue_page`), fed by one engine subscriber that returns at once with no client connected. The phone page is a second Vite entry (`ui/remote.html`, `ui/src/remote/`) that imports `lib/api.ts` **types only** and never `@tauri-apps/*` (guarded by `remote/imports.test.ts`); the server serves exact embedded-asset hits only (Tauri's resolver falls back to `index.html`) and proxies Vite in debug builds. Phone-supplied covers are limited to TIDAL images at the RPC boundary (they reach SMTC/Discord); favorite toggles from any surface go through `AppState::favorite_changed` (desktop `favorite_changed` event + SSE `favorite`); the phone uses Dynamic color via the allowlisted `analyze_cover` and the pure `lib/coverPalette.ts`.
- Track 10 state (all under `%APPDATA%\OxiTide\config\`): `session.rs` (queue/position/shuffle/repeat restore, `session.json`), `history.rs` (`history.jsonl` + History/stats), `track_flags.rs` (content-blocking flags, `cache/track_flags.json`), `tray.rs` (tray menu/tooltip/close-to-tray, `ui.close_to_tray`), and `hotkeys.rs` (user-defined global accelerators via `tauri-plugin-global-shortcut`, `[hotkeys]`, empty defaults; once a chord is registered the global handler is the only delivery path).

- Distribution (Track 12, spec `2026-10-13-oxitide-track12-distribution-design.md`, runbook `docs/release.md`): `.github/workflows/ci.yml` runs the Rust and UI gates on Windows + Ubuntu 22.04 (UI build first: `generate_context!` needs `ui/dist`); `release.yml` turns a `vX.Y.Z` tag into a **draft** release via `scripts/release/` (`check-version.mjs`, `make-manifest.mjs`; tests: `node --test scripts/release/release.test.mjs`). Updater artifacts come only from the `tauri.release.conf.json` overlay (so local `app:build` needs no key). Self-update lives in `crates/oxitide-app/src/updater.rs` (`tauri-plugin-updater`, called from Rust; thin commands in `commands.rs`, all `NOT_EXPOSED` to the phone remote; `[updates] check_on_start`). Windows shutdown work is `run_exit_work` in `main.rs` — the Windows updater ends the process without `RunEvent::Exit`, so install calls it first. The updater minisign key is not a code-signing certificate; Windows code signing is deferred.

## IPC contract

- `invoke` sends camelCase args; Rust params stay snake_case (`redirect_url` ↔ `redirectUrl`).
- Payload field names are inconsistent and driven by serde attributes (`Track.audioQuality` is renamed, `HomeItem.item_type` is verbatim). Rust DTOs are the source of truth — keep `ui/src/lib/api.ts` interfaces in sync by hand.
- The phone remote's RPC mirrors `invoke`: `{method, params}` with camelCase params mapped onto snake_case in `remote/rpc.rs`; errors are `"<code>: <message>"`. Its wire types (`RemoteState`, `RemoteQueuePage`, …) are camelCase and mirrored in `api.ts` like any DTO.
- Auth is PKCE with a browser + paste-back redirect (no embedded webview); `auth_restore` silently refreshes on startup.

## Testing / security quirks

- HTTP tests use `wiremock` and must never hit the live TIDAL API.
- Tokens live in Windows Credential Manager via `KeyringStore` (service `oxitide`, user `tidal`); unit tests must use `MemoryStore`. Never log token values (`TokenSet` has a redacting `Debug` impl). Track 8 adds a Linux backend; note that keyring v3 silently falls back to its mock store if no platform feature is enabled.
- GUI smoke checks require a human, a real account, and a browser login; record them as checklists in `docs/superpowers/plans/notes/`.
- Component tests are jsdom per file (`// @vitest-environment jsdom`) via `@testing-library/svelte`; pure-logic tests stay on node. Modal focus handling lives in `lib/focusTrap.ts`, `lib/portal.ts` and `lib/dialogs.svelte.ts`; route titles in `lib/titles.ts` (with the skip link in `App.svelte`).

## Performance harness

Track 3's measurement gate lives in `scripts/perf/` (manual; no CI):

- Windows-only exemption (Track 8, T8-D3): the scripted runner/driver (`run-scenario.ps1`, `drive.mjs`) speaks the WebView2 CDP endpoint and is not ported to WebKitGTK. On Linux the `/proc` metrics in `crates/oxitide-app/src/perf.rs` keep process-relative marks, memory, and playback rows measurable via `OXITIDE_PERF_SCENARIO` + `node scripts/perf/check.mjs`; frame/interaction budgets stay unmeasured until the deferred harness port. Authority: `docs/superpowers/plans/notes/2026-10-03-track8-perf-exemption.md`.
- `powershell -ExecutionPolicy Bypass -File scripts/perf/run-scenario.ps1 -Scenario <S1..S10> [-Runs n] [-Manual] [-SkipCheck] [-Minutes n]` — launches the debug exe (Vite must be warm; the script starts it if port 1420 is free) and drives the scenario over the WebView2 CDP endpoint. Raw JSONL lands in the gitignored `.superpowers/perf/runs/`.
- `node scripts/perf/check.mjs` (or `npm --prefix ui run perf:check`) aggregates the corpus against `scripts/perf/budgets.json` (mirrors spec §4.2) and exits non-zero on any breach.
- Scenarios: S1 cold start, S2 warm start, S3-miss/S3-hit TTFS, S4 gapless advance, S5-instrument/S5-atmosphere scroll, S6 10k filter/sort/album, S7 10k queue build, S8 cache loop, S9 2 h soak, S10 manual stability. S4/S8/S9/S10 are human-in-the-loop (real account/audio); the rest are scripted.
- Conditions matter: single app, foreground, Vite warm, no deliberate background load. The current budgets and the S4 documented finding are recorded in `docs/superpowers/plans/notes/2026-10-02-track3-phase-d.md`.

## Workflow

- Feature work is spec'd/planned as dated files in `docs/superpowers/specs/` and `docs/superpowers/plans/`; extend that series instead of inventing new structure. `.superpowers/` is gitignored brainstorm/session state.
- Legal/security surface: root `LICENSE` (AGPL-3.0-or-later) and `THIRD_PARTY_NOTICES.md`; the webview CSP lives in `crates/oxitide-app/tauri.conf.json` (`csp` + `devCsp`) — update the allowlist when adding a remote origin.
- Windows-first: `keyring` uses `windows-native` on Windows; non-Windows builds use output/media/scheme stubs until Track 8 (Linux support).
